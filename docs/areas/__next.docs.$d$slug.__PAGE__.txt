3:T1f0b,<p>An <strong>area</strong> is a topic somebody asks about. Not a directory, not a module, not a route — a topic.
&quot;Custom domains&quot; is an area. &quot;<code>src/lib/utils</code>&quot; is not.</p>
<p>Areas are the unit of extraction: KIRA reads one area&#39;s files together, writes the facts it found,
and records a hash so an unchanged area is skipped next time.</p>
<h2>What <code>kira init</code> proposes</h2>
<p><code>kira init</code> looks for the first routes root it recognises — <code>src/app</code>, <code>app</code>, <code>src/pages</code>, <code>pages</code>,
<code>src/routes</code>, <code>routes</code> — and proposes one area per page directory beneath it, deriving the route as
it goes. Route groups like <code>(marketing)</code> are not part of a URL and are walked through; dynamic
segments become <code>:name</code>.</p>
<pre class="shiki shiki-themes github-light github-dark" style="--shiki-light:#24292e;--shiki-dark:#e1e4e8;--shiki-light-bg:#fff;--shiki-dark-bg:#24292e" tabindex="0"><code><span class="line"><span>src/app/project/[id]/domains  →  id: project-domains</span></span>
<span class="line"><span>                                 route: /project/:id/domains</span></span>
<span class="line"><span>                                 audience: end_user</span></span></code></pre><p>It then proposes an area per child of the behaviour roots — <code>src/lib</code>, <code>src/services</code>, <code>src/server</code>,
<code>src/api</code>, <code>src/agents</code> — with <code>audience: operator</code>, since those describe how the product behaves
rather than what a screen looks like. A <code>docs/</code> directory becomes one more area.</p>
<p>Directories that never hold product knowledge are skipped outright: <code>components</code>, <code>hooks</code>, <code>utils</code>,
<code>types</code>, <code>styles</code>, <code>assets</code>, tests and mocks.</p>
<h3>Thresholds differ by kind</h3>
<p>A page directory is user-facing by construction, so <strong>one file is enough</strong> to make it an area — a
single-file <code>login/</code> page owns &quot;how do I reset my password?&quot;, which is one of the most-asked
questions any product gets. Under a behaviour root a lone file is usually a utility, so it needs at
least two to qualify.</p>
<p>The proposal caps at 24 areas. If more survive, <code>init</code> says how many it dropped rather than
silently truncating.</p>
<h2>What you should change</h2>
<p>The proposal is a first draft whose only job is to be worth editing.</p>
<ul>
<li><strong>Merge what a person would ask about together.</strong> Three sibling route folders that make up one
feature are one area, not three.</li>
<li><strong>Delete what has nothing user-facing.</strong> <code>not-found</code>, <code>layout</code>-only folders, internal admin
pages nobody outside the company sees.</li>
<li><strong>Rename for the reader.</strong> <code>project-domains</code> is a path; &quot;Custom Domains&quot; is what your user calls
it, and the name reaches the model at extraction time.</li>
<li><strong>Set the audience.</strong> <code>end_user</code> for people using the product, <code>operator</code> for support and
internal staff, <code>developer</code> for engineers. It decides both how facts are written and who they
are shown to.</li>
<li><strong>Fix the route.</strong> The area&#39;s route is a hint; the extractor refines it per fact from the file
paths it reads, so a fact from <code>positions/edit/[id]/page.tsx</code> ends up at <code>/positions/edit/:id</code>
even when the area says <code>/positions</code>.</li>
</ul>
