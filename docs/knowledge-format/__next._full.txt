<h3><code>route</code> and <code>requires</code> are the interesting ones</h3>
<p>No documentation-grounded tool can fill these, because no article has them. A route means the
assistant can hand the reader a working link rather than describing where to click, and it means
the same question can be answered differently depending on the screen they are on. A gate means a
fact about a Business feature never reaches a Free user — telling them how to use something they
cannot reach is worse than saying nothing.</p>
<p>The extractor fills <code>requires</code> only when the code gates the thing explicitly. A guess there
silently hides a fact from people who should see it, so the instruction is to leave it empty
unless the gate is in the source.</p>
<h2>The eight types</h2>

<th>What it holds</th>

<td>A capability that exists.</td>
</tr>
<tr>
<td><code>workflow</code></td>
<td>An ordered way to accomplish something; steps in order in the body.</td>
</tr>
<tr>
<td><code>concept</code></td>
<td>A term or model the reader needs to use the product.</td>
</tr>
<tr>
<td><code>ui_location</code></td>
<td>Where something lives in the interface.</td>
</tr>
<tr>

<td>A question users actually ask, with its answer.</td>
</tr>
<tr>

<div class="callout tint-brand"><div class="callout-label">Important</div><div class="callout-body"><p><code>boundary</code> is the type that earns the product its promise. Most wrong answers in this category
are not hallucinated features — they are a confident <em>yes</em> to something the product refuses. The
extraction prompt mines guards, plan checks, validation errors and unsupported branches as hard
as it mines capabilities.</p>
</div></div><h2>What never appears in the text</h2>
<p>For <code>end_user</code> and <code>operator</code> audiences, <code>title</code>, <code>summary</code> and <code>body</code> may not contain repository
names, file paths, function or class names, database tables, environment variables, internal API
routes, queue or cron identifiers, or developer tooling. Paths live in <code>sources</code> and nowhere else.</p>
<p>Interface strings go the other way: they are quoted <strong>exactly</strong> as the code renders them —
<strong>Add existing domain</strong>, <strong>Save Changes</strong>, <strong>Total must equal 100% to save changes</strong> — because that
is the string the reader has to find on screen. They are never translated, even when the answer
around them is in another language.</p>
<h2>Provenance and staleness</h2>
<p><code>extracted.area_hash</code> is a digest of every source file in the area — sorted paths plus contents, so
a rename changes it too. <code>kira status</code> compares it against the current files and reports <code>fresh</code>,
<code>stale</code>, or <code>not yet run</code>.</p>
<p>An area that legitimately produced zero facts is indistinguishable from one that was never
extracted, so the run is also recorded in <code>.kira/extracted.json</code>. Commit that file with the rest.</p>
